# ЛР3: аналіз продуктивності PostgreSQL за допомогою PoWA

Проєкт реалізує практичну частину ЛР3. Він створює навантаження на PostgreSQL, записує найресурсомісткіші запити, збирає план `EXPLAIN (ANALYZE, BUFFERS)` та статистику WAL.

## Передумови

- Встановлено PostgreSQL 18, а служба `postgresql-x64-18` запущена.
- Встановлено Python 3.14.
- Пароль облікового запису PostgreSQL вводиться локально, коли його запитує `psql`. У проєкті пароль не зберігається.

Для інтерфейсу PoWA встановіть PoWA окремо або використайте офіційний Docker-образ PoWA. SQL-статистика збирається з того самого джерела, яке використовує PoWA: `pg_stat_statements`.

## Встановлення PoWA через Docker

Docker Desktop має бути запущений. У цьому проєкті використовується ізольований PostgreSQL 18 з розширеннями PoWA, тому локальний PostgreSQL не змінюється.

Запустіть PowerShell у папці `LR3`:

```powershell
.\start-powa.ps1
```

Після запуску відкрийте [http://localhost:8888](http://localhost:8888). У PoWA буде доступний сервер `local-powa`. PostgreSQL контейнера доступний локально на порту `55432`, а дані зберігаються у Docker volume `lr3_powa_powa-data`.

Для виконання навантаження саме в PoWA-базі запустіть окремо:

```powershell
.\run-lab.ps1 -Seconds 60 -Port 55432 -Database powa
```

Для цього навчального контейнера скрипт автоматично використовує тестовий пароль `postgres`. Для вашого локального PostgreSQL залишайте стандартний порт `5432` без параметра `-Port`.

Зупинка PoWA:

```powershell
.\stop-powa.ps1
```

Цей варіант використовує тестові облікові дані тільки всередині локального навчального контейнера: користувач `postgres`, пароль `postgres`, база `powa`.

## Запуск

Відкрийте **SQL Shell (psql)** або звичайне вікно PowerShell і виконайте:

```powershell
Set-Location F:\Chdtu\Monitoring\LR3
.\run-lab.ps1 -Seconds 60
```

Скрипт попросить пароль у терміналі. Якщо `pg_stat_statements` не завантажується під час запуску, додайте цей параметр у `postgresql.conf`, перезапустіть службу PostgreSQL і повторіть запуск:

```text
shared_preload_libraries = 'pg_stat_statements'
```

Після виконання будуть створені файли:

- `results/top_queries.tsv` - 10 запитів із найбільшим сумарним часом виконання;
- `results/explain.txt` - план виконання з інформацією про буфери;
- `results/wal.txt` - поточні лічильники WAL.

## Що зафіксувати в PoWA

1. На вкладці **General Overview** зафіксуйте кількість запитів, загальний і середній час до та під час навантаження.
2. На вкладці **Details for all queries** перенесіть 5-10 запитів із `results/top_queries.tsv` та поясніть вартість кожного.
3. На вкладці **Wait Events** зазначте, чи очікує навантаження на IO, Lock, Client або інші події.
4. На вкладці **WALs** порівняйте кількість WAL-байтів до та після тесту. Навантаження переважно читає дані, тому приріст WAL має бути невеликим.
5. За `results/explain.txt` поясніть послідовне сканування, JOIN, сортування та попадання/читання буферів.
